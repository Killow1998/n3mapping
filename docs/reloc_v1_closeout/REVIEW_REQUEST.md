## 1. 系统在做什么

ROS2 Humble 的 LiDAR SLAM + 重定位。传感器只有 **LiDAR + IMU，无气压计、无 GNSS**。
目标平台 **RK3588 / Jetson Orin NX / Orin Nano**，算力是硬约束。
机器人是四足，**雷达倾装**（实测本体 z 轴离重力 9.7°–18.25°，随姿态变化）。

重定位链路：RHPD 描述子检索 → top-K 候选 → 每候选做 GICP → 多假设在 5 帧时间窗内累积证据
→ 排序（可见性证据为主键）→ 接受门（loglik / margin / winner_streak /
converged_updates / moving_visibility / ambiguity）→ FULL_6DOF_LOCKED。

## 2. 当前状态

**产品合同**：today20 ≥15/20 正确 FULL、**零错误 FULL**、平移 ≤0.50 m、yaw ≤3°、
roll/pitch ≤2°、获取 <5 s、backend p95 <1 s。用户明确表示**「不能误锁」优先于成功率**
（宁可不锁也不锁错）。

| 20 case（today20，全流水线） | 正确 | 错误 | 不锁 | 灾难性 >5 m | 最坏 |
|---|---|---|---|---|---|
| baseline `72fa6f7` | 12 | 5 | 3 | 3 | 33.097 m |
| **+ 自由空间 veto**（本分支） | **12** | **2** | 6 | **0** | **1.132 m** |

剩下 2 个「错误」都不是错地方：1.13 m 和 **3 cm + 姿态 2.46°**。

**跨 session 独立数据**（2026-03 的 floor7 bag 打 2026-07 的图，无 GT）：
6 组 → 4 锁 / 2 不锁 / **零错锁**。零错锁有硬证据：同一 bag 的**冷启动 5 秒片段**
与**已跟踪 60 秒的全长段**在同一时间戳比对，**位置差 0.013 m、姿态差 0.2°**。

**仍不达标**：正确 12/20（要 15）、错误 FULL 2（要 0）、获取时延 10.4–12.4 s（要 <5 s）、
p95 多例 >1 s。

## 3. 核心难题（一句话）

**感知别名。** 同一层楼的走廊/房间在 LiDAR 观测下高度相似。
worklog §44–59 记录了**六种独立方法全部无法把真值从别名中分离**：

1. 累计对数似然
2. 可见性一致性比
3. 可见性证据对数几率
4. ICP fitness / 内点率
5. TEASER++ 最大团（**别名团是真值的 2.3 倍，且精确命中别名位姿**）
6. 3D 占据 + 自由空间栅格（今日新增，§72.3）

RHPD 检索本身没问题（真值 20/20 在 rank≤4），ICP 也没问题（种子正确时厘米级）。
**失败点唯一地在「从 top-K 中选出真值」。**

唯一被证明有效的机制是**证据不足时拒绝下结论**——不试图从不可分的数据里榨取区分度。

## 4. 开放问题（最想要外部意见的地方）

### Q1：召回 12 → 15，除了「等机器人走动」还有别的路吗

现有 6 个不锁里，3 个是 veto 正确挡下的（真值本来就没赢，不该指望变正确），
要涨的是另外 3 个。已验证的前提：**别名会被行走证伪**——
11-46-29 的累计票差在 3.69 m 行程内从 0 拉到 11.183，单调。

所以工作卡 C/D 是「假设持久化 + 可逆决策状态机」：
现在 `clearRelocHypotheses()` 位于 accept/reject 之后，每次接受失败就销毁全部证据，
假设集最多活 5 帧；实测每个 episode 积累的视角基线峰值只有 1–3 cm，
**而机器人实际走了 0.74–12 m**——系统永远在近静态快照上做终局决定。

**问题**：这是唯一的路吗？有没有在不移动的前提下引入新信息的办法？
（注意：无气压计、无 GNSS、无 WiFi/UWB 假设。）

### Q2：锁定时刻 ~2° 的姿态误差，机制未明

11-54-55：平移 **3 cm**，姿态不变量误差 **1.989°**（合同限 2°），误差轴≈map x。
误差是**暂态**：锁定帧最差，随后 ~35 帧跟踪自行收敛到 0。

已证伪五个假设（§74）：地图倾斜、聚合窗口抹平、信息矩阵可观测性不足、
求解器停止判据过粗、地图与轨迹姿态不一致（实测一致到 **0.004°**）。

**未解释的矛盾**：GICP 在 **2 次迭代、内点率 1.0、fitness 0.087** 下收敛
（即接受了种子姿态几乎未修正）；若它对 map-x 方向的旋转确实不敏感，
**信息矩阵的旋转块最小特征值为什么不反映**（2.94e6，高于三个正确案例）？

### Q3：veto 的时延代价

veto = 自由空间最优与可见性 top1 不是同一物理位姿时拒绝锁定。
它在**单窗口**上只否决不新增接受；但 `clearRelocHypotheses()` 会在 accept/reject 后
无条件清空全部状态，所以 **episode 级并无「不制造错锁」的结构保证**（§76）。
代价是在跨 session 数据上把获取时延推到 10–12 s。
**有没有既保住零错锁、又不让系统长期停在搜索态的结构？**

### Q4：评测方法本身

today20 的参考是 `same_run_dense_optimized_reference`——**建图那次运行自己的优化轨迹，
不是独立 GT**；20 个 query 本身也是那次遍历的时间切片（395.6 s / 824.9 s），
留出性完全依赖 exclusion windows。

今天有一次直接翻车（§73）：一个离线选择器在 **12 案例子集**上得到 9/3/0，
接进流水线后把一个 baseline 正确的案例从 0.041 m 打成 32.924 m——
**因为那个子集恰好排除了唯一的反例**。

**问题**：在只有这批数据的前提下，什么样的评测协议能避免这类自欺？

## 5. 请不要重提的路线（已实测证伪，附出处）

| 路线 | 结论 | 出处 |
|---|---|---|
| 换排序主键 / 描述子选择替代几何重排序 | 闸门一到位，top-K 内部怎么排**净效果为零** | §68 |
| 自由空间当**选择器**（kill 被支配假设） | 杀到只剩 1 个 → `top2=nullptr` → `margin=inf` → **歧义闸门被整体解除**；毁掉一个正确案例（0.041→32.924 m） | §72.3 |
| 5σ 二项采样噪声做淘汰门槛 | **伪判据**：真值/别名分差 0.144，5σ=0.035，度量的是采样噪声而主导误差是模型误差 | §72.3 |
| 绝对阈值否决器（free% 超过某值即否决） | 真值 free% 0–60.92% vs 灾难性 0.11–71.04%，**完全重叠** | §70 |
| 2D 投影栅格 | 高度被压掉 → 真值自身被判为矛盾；最坏错锁 10.009 m | §70 |
| 地图整体倾斜 4.14°、重力对齐修复 | **伪影**（单平面拟合跨 265 m）；局部地板法向 0.41°；且刚性去倾斜在度量上**恒等无效** | §69 |
| 别名是跨楼层 | 全部同楼层；地板 z 跨度 7.41 m 是同层多标高 | §56、§72.4 |
| 提高 GICP 旋转停止判据（1.0°→0.1°） | 20 case **逐位完全相同**；求解器 2 次迭代即收敛，未被判据截断 | §74.4 |
| 用配准信息矩阵做可观测性闸门 | **不可分**：roll 误差最大的案例信息量高于三个正确案例；CRB 预测 σ 与实测差 25–100 倍 | §74.3 |
| 学习式验证器 / 模型训练 | 用户明令禁止 | 约束 |
| 按 bag / 按 case 调阈值 | 用户明令禁止 | 约束 |
