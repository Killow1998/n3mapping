## 一、最重要的五件事

### 1. 重定位的决策是同义反复

锁定要过七道闸,**其中四道是排序量的下游函数**:

| 闸 | 证据来源 |
|---|---|
| `pass_margin` | ← 可见性证据 |
| `pass_winner_streak` | ← 谁是 top1,由可见性证据决定 |
| `pass_moving_visibility` | ← 可见性证据 |
| `!ambiguous` | ← 可见性证据 |
| `pass_loglik` | 配准 |
| `pass_converged_updates` | 配准 |
| `pass_free_space` | 自由空间栅格(唯一独立) |

于是"决策"等价于**"最好的那个是最好的"**。

**实测印证**:改一个可见性相关的量,四道闸同时松,`algorithm_lock` 15→20。

### 2. 该用来判断的量都已经存在,只是没接到判决上

| 量 | 现状 |
|---|---|
| 配准信息矩阵(6×6) | 每次配准都返回、存进每个假设、每次锁定都打印,**没有任何闸读它** |
| 三态自由空间 + 二项标准差 | 有,但被限制成一个 argmax 身份比较 |
| 邻域共识(中位数 + MAD) | 建图侧有且是主导项(权重 0.35),**重定位侧完全没有** |
| 地板高度直方图 | 建图侧有,重定位判决不用 |

**缺的不是信息,是把信息接到判决上。**

### 3. 验证逻辑被分成两半,而且是不重叠的两半

grep 确认:

```
  闭环侧    完全不用自由空间/可见性
  重定位侧  完全不用邻域共识
```

**不是"两边做重复的事",是"本该相同的事各做了一半"。**
决定合并成一个验证模块(见 §3.6)。

### 4. 关键帧间距 1.0 m,Part A 的格子 4.29 m

```
  ┌────────── 一个 Part A 格子 (4.29 m) ──────────┐
     kf0    kf1    kf2    kf3    kf4
      1m     1m     1m     1m
```

**连续四个关键帧落在同一格,Part A 设计上就分辨不出它们。**
Part B 的环是 1.875 m,细 2.3 倍 —— 这是 Part B 召回 38% 优于 Part A 26% 的
最直接解释,纯几何。

### 5. 两道契约门在整整一轮实验里从未被评估

```
  peak RSS max:    770.8 MiB   门 <600    超 28%
  strict p95 max: 2238.88 ms   门 <1000   超 2.2 倍
```

评分器在打印内存那行崩溃(读一个不存在的旁路文件),下一行的 p95 从未执行到。
**即使锁定全部修对,契约照样过不了。**已修评分器;归因未做,但 RSS 各臂恒为
770.x MiB,与本轮切换的机制无关。

## 二、重复出现的错误形状

**同一个错误出现了四次:用一个测得准的量,去代理一个它并不测量的性质。**

| 量 | 它实际衡量什么 | 它被当成什么用 | 后果 |
|---|---|---|---|
| ICP `fitness` | 残差大小 | 是不是同一个地方 | 错的地方拿到 fitness 0.0131 / inlier 1.000 |
| 可见性 `consistency` | 地图在这里有多厚 | 位姿对不对 | 走过两趟的地方被罚 2.2 倍 |
| PCA `confidence` | 主轴方向定得准不准 | Part A 有没有区分力 | 走廊里给满权重,而走廊正是它最没用的地方 |
| `predicted_translation_norm` | 漂移位姿报告的间距 | 这个闭环可不可信 | 拒掉了最能修复漂移的那些闭环(已修,记录在代码注释里) |

第四条是**已经被识别并修掉的**,而且注释写得很清楚。前三条还在。

**这个形状的共同点**:被代理的性质通常**没有直接的测量**,于是有人找了一个
"看起来相关、而且算得出来"的量顶上。相关性在多数情况下成立,
**在最需要它的边缘情况下反转**。

## 三、九个模块

### 3.1 重定位决策(`world_localizing.cpp`,2290 行)

**框架**:多假设 + 时序累积。家族选型正确。

```
  提议 ──→ 打分/更新 ──→ 决策
   │         │            └─ 七道闸全过 → 锁定;否则"这帧先不锁"
   │         └─ 对每个存活假设重新配准,累加证据
   └─ 假设集为空时:描述子搜索 → 候选位姿评估 → 播种假设
```

`relocalize()` 是 **1125 行的单个函数**,占全文件一半。

**问题**:

1. **决策由打分派生**(见 §1.1)
2. **没有归一化**。假设有 `cumulative_log_likelihood`,但没有归一化成后验,
   所以框架**无法回答"最优假设占多少概率质量"**。margin 是两个未归一化分数之差,
   尺度随工作点漂 —— 遮挡感知把 consistency 从 0.42 推到 0.84,
   logit 在那里陡 4 倍,同样的证据差读出 10 倍的 margin,固定阈值 0.35 立刻失效。
3. **证据在重叠观测上累加**。查询云是 5 帧滑窗,每次调用推进一格,
   相邻调用共享 4/5 数据,而似然是逐次求和 —— 等于把同一份观测数了五遍。
   推论(强,属推理):**置信度随时间单调增长,与是否真有新信息无关**。
4. **状态机只有两态,没有"放弃"**。14 个拒绝理由全是"这帧先不锁"。
   **走廊混叠是环境性质,不是等下去会消失的东西。**

**修法**:3 → 2 → 1(先让系统能说"不知道",再让置信度有稳定尺度,最后补独立验证)。

### 3.2 自由空间 / 可见性(`free_space_grid.cpp` 195 + `visibility_consistency.cpp` 225)

**框架**:两个组件回答同一个问题,能力差得很远。

| | `FreeSpaceGrid` | `VisibilityConsistency` |
|---|---|---|
| 表示 | 3D 占据+自由栅格,Cartographer 式射线 | 球面深度图,每方位取最近点 |
| 状态 | **occupied / free / unknown 三态** | **只有两态** |
| 覆盖 vs 矛盾 | **分开** | **混在一个分母** |
| 不确定性 | **有**(二项标准差) | **无** |
| 阈值 | **不用发明**(差异须超过测量噪声) | 固定常数 |
| 角色 | **只否决** | **主排序键 + 四道闸** |
| 开关 | **环境变量** | config |

**装反了。**好的组件被限制成 argmax 比较,差的组件在做决定。

**`VisibilityConsistency` 的缺陷在表示层,不是参数**:深度图由地图**点**构成,
点只标"占据",所以**"地图知道这里是空的"与"地图对这里没意见"不可区分**。
走过两趟的地方点更多 → 取 min 拉短预测距离 → 记为矛盾。
这就是那个 2.2 倍,**不是调参能修的**。

**`FreeSpaceGrid` 头注释里记着实测**:2D 投影留下 10 m 错锁;改 3D 后最坏错锁
**33.1 m → 1.1 m**;分辨率 0.15/0.20/0.25 逐 case 相同(**是高原不是调出来的点**),
0.10 崩、0.30 复发。

**好组件由环境变量控制**:`N3MAPPING_FREESPACE_SELECT` / `_MODE` /
`RELOC_PERSIST` / `_MAP_PCD` —— 不进 config、不进 `runtimeConfigCanonical`、
不进 provenance、守卫测试覆盖不到。**一次运行的行为取决于没有被记录的东西。**

**修法(四步,每步单独测)**:

1. 四个环境变量升成 config 字段(零行为变化,provenance 立刻有意义)
2. 退化检测进判据(零算力,信息矩阵已经在算)
3. 自由空间否决做实(从 argmax 比较改成用 `value ± stddev` 做可分性检验)
4. **前两步生效后**,才动可见性的表示偏差

第 4 步有个可检验的预测:**上次遮挡感知导致 `algorithm_lock` 15→20,
是因为四道闸都在它下游;闸独立之后重跑同一改动,不应再出现该跳变。**
预测若不成立,说明对因果的理解仍是错的。

### 3.3 地图资产 IO(`localization_atlas` 481 + `map_serializer` 577 + 其他)

**框架**:常驻三份物化。

1. 关键帧点云(257 帧)—— 真值来源
2. 拼装的全局点云 —— 给自由空间栅格、给 `cropGlobalMap`
3. **`prepared_target_`** —— 纯粹为速度存在

第 3 份是大头:small_gicp 每点存 points + normals + **4×4 协方差**,
约 192 B/点,**协方差比点本身大 5 倍**。这是 GICP 的固有成本,不是浪费。

**atlas 是正当的速度权衡**(搜索期 10 候选 × 195 帧,每候选现场准备会是灾难),
**但形式有三个问题**:

1. **全有或全无**:要么全图预备(770 MiB),要么每次现场准备。
   没有"按邻域惰性准备 + 有界缓存"这个中间档,**而 RK3588 需要的正是它**。
2. **它改的不只是速度,是语义**:带 atlas 时 GICP 收敛盆地是**整张地图**,
   不带时限制在**局部子图**。两个不同的算法,藏在一个读起来像纯缓存的抽象后面。
3. **配准与可见性用的目标云不同**:配准对全图(有 atlas 时),可见性对局部子图。
   同一候选,两个证据看的不是同一份东西,却被放在一起比较和累加。**这是缺陷。**

**已有的数否掉了"分块加载"**:

```
  prepare_ms  608.560      从原始点云算
  verify_load_ms 434.389 + verify_kdtree_ms 236.201 = 670  从盘上读回并重建树
```

**KD-tree 没有被序列化**,加载并不比计算快。所以该做**惰性计算 + LRU 有界缓存**,
不做分块加载。这一次修掉上面三个问题。

### 3.4 配准(`point_cloud_matcher.cpp`,427 行)

**框架最健康的一块。**接口给了该给的:

```cpp
struct MatchResult {
    Eigen::Isometry3d T_target_source;
    double fitness_score, inlier_ratio;
    Eigen::Matrix<double, 6, 6> information;   // 完整信息矩阵
    std::vector<MatchStageResult> stages;      // 逐阶段诊断
};
```

`prepareTarget` / `prepareSource` 分离正确(一个查询试 4 个 yaw 种子,准备一次复用)。
多分辨率 `{base×2, base}` 两层 + 可选 refine 层,分工合理。

**问题全在边界**:

1. **输出对了,消费错了**。`fitness_score` 在前、最像"质量";`information` 在最后。
   消费者读前者。
2. **单向 ICP,而且代码里写着**:"prevents one-way ICP from dragging a valid pose
   onto a remote dense surface" —— 已知缺陷,**但对策是在下游加可见性检查,
   而那层补丁本身又成了 §3.2 的问题源**。
3. **atlas 可能让每次配准变慢**(假设,未验证):搜索期每帧最多
   10 候选 × 4 yaw = 40 次 `alignPrepared`,195 帧 = 7800 次,而目标是整张地图。
   atlas 省的是 O(1) 次准备,付的是 O(7800) 次查询。

**这一块本身不需要重构,要做的是让调用方用对。**

### 3.5 图优化(`graph_optimizer.cpp` 763)

**框架**:GTSAM iSAM2 增量 + 批量兜底,带回滚与健康检查;鲁棒核可配;
因子有先验、里程计、闭环、**地板姿态**。

**地板姿态因子是好设计**:从关键帧自己测的地板法向给绝对 roll/pitch,**yaw 留自由**
—— 这正是重力能说与不能说的边界。

**顺序约定正确,但没有任何东西保护它**:

```
  small_gicp H              [旋转; 平移]
    ↓ copyInformation 交换
  MatchResult::information  [平移; 旋转]   ← n3mapping 内部约定
    ↓ world_localizing 读 block(0,0)=平移、block(3,3)=旋转      ✓
    ↓ createRobustNoiseModel 交换回来
  GTSAM Pose3               [旋转; 平移]                        ✓
```

三处必须同时正确,**没有一处写下这个约定**,没有测试保护。
谁在任一端"修正"一下,旋转刚度就加到平移上,**不会有任何测试变红**。

**核心问题:用配准 Hessian 当相对位姿协方差,系统性过自信。**

GICP 的 `H` 衡量"**在它自己找到的那组对应下**,残差对位姿的约束有多强"。它不含:

- 那组对应可能对到了别的地方
- **目标子图自己是歪的**(闭环配的正是一张已漂移的地图)

```
  闭环 z 精度 0.376 m  ≈  残差跨度 0.434 m
```

这个约等号就是循环依赖被量出来的样子。**过自信的边把误差固化,而不是让图吸收。**
也解释了 `loop_axis_weighting` 为什么失败:**问题不在各轴比例,在整体尺度就偏小**。

**修法参考 GLIM**(声明:未读源码,对公开描述的理解,信心中等)。
GLIM 不把配准冻结成"相对位姿 + 协方差",而是把 **matching cost 本身**做成因子,
在当前位姿估计上求值 —— 位姿一动就重算。用 VGICP 让求值便宜,再上 GPU。

**为什么正好解我们的问题**:图优化一轮之后目标已经没那么漂了,**但冻结的边不知道**。

三档(**建图是离线的**,这里有余量):

- **档 A(推荐先做)**:迭代式重线性化。`repeat k: optimize() → 用优化后位姿
  重新配准每条闭环边 → 更新边`。不需要新因子、不需要 GPU,42 条边 × 2~3 轮 ≈ 百次配准。
- **档 B**:自定义 GTSAM 因子(GLIM 的 CPU 版),误差就是体素化 GICP 代价,给解析雅可比。
- **档 C**:只给协方差加一项反映"目标自身不确定性"的量。最便宜,不解决根本。

**风险**:迭代重配准可能**强化**一个自洽的错误闭环。所以鲁棒核保持开启、
轮间大幅跳动的边记为不可信,**主判据用地板残差段间跨度而非重访 p90**
—— 重访配对的正是闭环约束的关键帧。

### 3.6 闭环验证(`loop_consensus_verifier` 479 + `loop_verifier` 238 + `loop_segment_consistency` 239 + `loop_referee.h` 132)

**这一块的框架是对的,而且它实现了重定位侧缺的那个东西。**

```cpp
energy = 0.20·descriptor + 0.10·spatial + 0.20·overlap
       + 0.20·local_map_consistency
       + 0.35·(segment_support × segment_consistency)     ← 最大权重
       - 0.05·(1 - temporal_gap)
```

**最大权重给了"邻近关键帧各自独立配准后是否互相一致"** —— ORB-SLAM 的共视一致性。

硬规则把独立性要求**明写出来**:

> Every accepted loop needs at least one confirmation **the drifted poses could not
> have produced**: a descriptor hit, or neighbouring keyframes registering
> consistently against the same match.

**代码注释里两条一流的实测洞察**:

- 只认描述子确认 → **丢掉 57 个最好候选里的 26 个**
- `predicted_translation_norm` 作拒绝依据 → **它恰恰对最能修复漂移的闭环最大**,
  拒掉了 86 个中位 fitness 0.052 的候选(已移除)

**这一块自己的问题**:三套机制(`LoopVerifier` / `LoopConsensusVerifier` /
`LoopSegmentConsistency`)都在算"邻域是否一致",口径与结构各不相同,
**没有一个单一的、有权威的判定**。

### 3.7 闭环检测(`loop_detector.cpp` 526)

**框架**:三条来源互斥。

```
  RHPD 主路(SC 辅助 + 否决)   有结果就 return
  Scan Context 兜底             只在 RHPD 无果时到达
  空间半径                      独立入口
```

**一个正确的模式在这里**:`SC 不参与选择,只用来否决 RHPD 的候选` ——
这正是 §3.2 里自由空间该有的地位。**同一原则,一处对一处错。**

**问题**:

1. `fused_score` 一个字段扛三种量纲(三条不混排,现在不是活 bug,但是陷阱)
2. `descriptor_score` 以权重 0.20 进裁判,而**两条路的归一化不同** ——
   同一把固定的尺子量两种不同标定的特征

**已修并记录在案**:SC 需要索引前缀、RHPD 不需要,旧代码让前者的限制吃掉后者,
**导致前 50 个关键帧从来没被检查过**。

**能不能只留 RHPD**:

- **SC 可以撤,但要等验证模块合并之后** —— 它现在是唯一的独立否决,
  虽然独立性弱(和 Part B 测的几乎是同一件事)
- **空间半径现在不能撤** —— 它正在扛实事,恰恰因为描述子召回只有 24%。
  前提是 RHPD 召回被修好且实测不丢闭环

### 3.8 描述子(`RHPDescriptor.cpp` 747)

**三步**:

```
输入点云 ─→ PCA 对齐(只绕 Z 转)
  对齐后点云 ──→ Part A(2352)  依赖对齐
  原始点云   ──→ Part B(512)   旋转不变
  原始点云   ──→ Aux (173)
```

**Part A** = 三个平面各 14×14 格 × 4 通道。记的是"东西摆在哪儿",必须先对齐。

**Part B** = 16 环 × 8 层 × 4 通道。**方位角只用来算方差,不进索引** ——
方差旋转不变,所以 Part B 天然不需要对齐。

**距离**:

```
  W(a,b) = sqrt( w_A·‖ΔA‖² + ‖ΔB‖² + 0.5·‖Δaux‖² )
  w_A    = 0.35 + 0.65·min(conf_a, conf_b)     ← Part B 权重恒为 1
  距离   = min( W(a,b), W(a翻转180°, b) )       ← PCA 定不出 ±180°
```

**PCA 置信度 = (l1−l2)/(l1+l2)**,即 XY 各向异性。
它衡量**主轴方向定得准不准**。设计逻辑自洽:主轴定不准 → 对齐不可靠 → 压低 Part A。

**但在我们的环境里门是反的**:

| 场景 | conf | `w_A` | Part A 在这里有用吗 |
|---|---|---|---|
| **走廊** | ≈1 | **1.0 满权重** | **最没用**(4.29 m 格分不出沿轴位置) |
| **空旷房间** | ≈0 | **0.35** | **最有用**(XY 布局最有区分度) |

**顺带**:PCA 对齐处有五条互相矛盾的注释提出四种 180° 约定,最后一条都没采用,
算出的计数被 `(void)` 显式丢弃。行为正确(flip 在 `distance()` 处理),
但说明**这段的约定从未被确定下来**。

### 3.9 建图主循环(`n3mapping_core.cpp` 1920)与关键帧(`keyframe_manager.cpp` 209)

**建图主循环是全仓库结构最健康的大文件** —— 一条线性闸门链,
每道闸有注释说明它为什么存在:

```
   1. 模式分派      LOCALIZATION / MAP_EXTENSION / MAPPING
   2. 帧有效性
   3. 里程计发散闸  "每多收一帧,就是用不可用的整图替换可用的局部图"
   4. 静止启动闸
   5. 关键帧判定
   6. 存储 + SC 描述子 + RHPD 描述子
   7. 先验 / 里程计边
   8. 地板姿态因子
   9. incrementalOptimize()
```

闭环走单独的 `processPendingLoopClosures()` —— **474 行,全仓库第二大函数**,
仅次于 `relocalize()` 的 1125 行。**两个最大的函数都在做"要不要相信一个匹配"。**

**关键帧**:`位移 ≥ 1.0 m 或 转角 ≥ 0.5 rad`,用 `pose_odom`(未优化)——
**正确**,决策必须因果。

**这一个纯几何阈值同时决定**:描述子采样密度、地图点云总量、闭环候选粒度、
子图空间跨度。**没有任何与"这一帧带来多少新信息"相关的判据**,
而它与描述子分辨率的**耦合没有在任何地方写出来**(见 §1.4)。
